## 2024-06-13 - Bounds checks in `Vec::push` for hot audio loops
**Learning:** In highly trafficked audio processing loops (like `Packer::pack`), calling `Vec::push` repeatedly incurs bounds checks that LLVM cannot always elide, even when `Vec::reserve` is used up front. Using `Vec::extend` with iterators allows LLVM to compute the necessary length and safely write elements without per-element checks, yielding a ~30-40% speedup in packing time.
**Action:** Prefer `extend` with iterators (like `.map()` or `.flat_map()`) over explicit `for` loops calling `.push()` when collecting fixed-size transformations in hot loops.
## 2026-06-13 - [LLVM PGO Pipeline for Bit-Perfect Player] **Learning:** [Profile-Guided Optimization (PGO) using `cargo-pgo` requires running a representative workload to generate `.profraw` files, merging them, and rebuilding. However, decoding simple WAV files is already heavily optimized and likely memory/IO bound or already fully utilizing SIMD (Symphonia features), yielding little to no measurable gain (~0.19s before and after on x86_64 host for 10-minute WAV dump).] **Action:** [When applying PGO to audio processing, ensure the representative workload heavily exercises branch-heavy logic (e.g., DSD to PCM conversion, resampling if added, or lossy format decoding like FLAC/MP3) rather than simple PCM unpacking to see measurable performance gains.]
